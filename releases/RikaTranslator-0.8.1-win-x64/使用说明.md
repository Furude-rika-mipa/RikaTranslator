# Rika Translator（梨花翻译工具）0.8.1 使用说明

适用于 Windows 10/11 x64。程序自带 .NET 运行时，需要 Microsoft Edge WebView2 Runtime。

## 开始使用

1. 将完整程序目录放到有写入权限的位置，双击 `RikaTranslator.exe`。
2. 在“AI 翻译”中添加自己的 OpenAI 兼容服务，填写地址和 API Key。
3. 点击“获取模型”后选择模型，也可以手动填写模型 ID；保存服务并主动测试连接。
4. 添加游戏实际使用的 EXE 或游戏目录，查看引擎识别、适配能力和安装计划。
5. 安装或卸载适配前关闭游戏。安装后运行游戏，并保持本工具运行。
6. 在游戏详情设置原文语言、目标语言、上下文、字体和译文；通过日志排查问题。

请整体保留 `runtime`、`wwwroot`、`adapters` 和 `licenses` 等目录。程序不是单文件应用。
首次运行会在程序旁创建自己的 `data`，分发文件不包含预设服务或个人 API Key。

游戏库卡片和列表均提供“移除”按钮；只移出游戏库，保留游戏文件、存档、字体与译文。已安装本工具适配时，请先在游戏详情卸载或恢复适配。

## 自动预读

默认在能可靠读取剧本时提前翻译，其他游戏继续逐句实时翻译。
当前句先翻译；随后后台将所选数量的后续对白合并为一次请求（1–10 句，默认 3），结果逐句缓存，播放时仍逐句显示。
支持已适配的 Flower Knight Girl Viewer 线性剧本及标准 RPG Maker MV/MZ 对话事件。
遇到选择、跳转、条件、脚本、变量修改或未知结构时停止预读，不执行未来指令，也不推进游戏。
Hook、Unity、Unreal、Ren’Py 和未匹配的剧本结构保留原有实时翻译。

开关和“预读句数”位于 **AI 翻译 → 翻译配置**，默认启用、3 句。当前句立即翻译，无需等待凑满预读句数。实际数量受安全边界和总计 8192 字符限制。
预读可能翻译到未播放的台词；关闭开关即可只翻当前已取得的文字。
批量结果校验失败不会写入错误缓存，当前句可自动退回单句翻译。

已经安装旧版 Viewer/RPG Maker 适配的用户，需要保存进度并关闭游戏，在新版工具中卸载旧的 Viewer/RPG Maker 适配后重新安装，再启动游戏使用预读。
程序在线更新只更换工具文件，不会直接覆盖正在使用的游戏插件。其他游戏无需为本功能重新安装。

## 字体制作（0.8.0）

1. 进入侧栏“字体制作”，选择本机 TTF/OTF 文件。
2. 可选择 Unity 游戏，程序按已识别版本选择对应系列模板；核对页面显示的真实 Unity 和 TMP 资产版本。
3. 选择常用简中、基本汉字（含繁体）或自定义字符，可补充人名、生僻字和符号。
4. 点击“开始制作”。默认采样 48、图集 4096×4096、留白 5，可在高级选项调整，最多 4 页图集。
5. 完成后检查缺字提示，点击“导出字体包”；或选好游戏后点击“用于选中的游戏”，确认字体设置并保存。

制作无需 Unity 编辑器、不调用翻译 API、不修改原字体。成品及报告保存在 `data/font-maker/generated`，可以取消任务。点击右侧“使用方式”下方的“打开字体文件夹”，可直接查看已生成的字体包和制作报告。
默认推荐 TMP 后备模式，以补充原字体缺少的字符；保存游戏字体设置时仍需遵守原有关闭游戏、安装与恢复规则。
提供 Unity 2018、2019、2020、2021、2022、6 模板，但无法保证同一系列全部版本通用。Unity 6 模板实际为 6000.4.0f1，尚未验证更早 Unity 6 游戏。
生成文件通过结构、字符及图集检查，具体游戏的材质、排版和显示效果仍需实测。原字体没有的字符无法通过加大图集补齐。

## 断开 Hook 与保留更新包

“AI 翻译”页的“断开所有 Hook 连接”停止当前 Hook 会话及其未完成请求并隐藏浮窗，保留连接偏好与字体设置，游戏可继续运行。
已经下载并校验的更新包在关闭软件后保留，下次启动离线复核后可直接安装；设置页可手动删除，安装成功会清理下载缓存。

## 翻译服务

支持 OpenAI 兼容 Chat Completions，基础地址和完整端点均可配置；支持 JSON 和 SSE 返回。
“测试连接”会向所选服务发送一次实际翻译请求，可能产生服务费用。
游戏原文及配置的上下文会发送给你选择的服务，请自行了解该服务的数据处理方式。

## 引擎适配

| 引擎 | 提供的适配路线 | 使用范围 |
| --- | --- | --- |
| Unity Mono | BepInEx 5 + XUnity.AutoTranslator | 自定义控件、TMP 和已有插件需逐款确认 |
| Unity IL2CPP x86/x64 | 匹配的 BepInEx 6 和 XUnity IL2CPP | 首次生成 interop 可能下载 Unity 基础库；版本兼容需确认 |
| Ren’Py 7/8 | 独立实时翻译插件 | 动态文字和布局需逐款确认 |
| NW.js / Flower Knight Girl Viewer | 场景对白异步翻译、本地中文菜单与设置 | 仅已适配的 Viewer 布局；其他 NW.js 网页尚未开放同等适配 |
| RPG Maker MV/MZ | JavaScript 翻译插件 | 图片按钮、自定义插件和复杂窗口可能不覆盖 |
| Unreal UE 5.7 Win64 | 固定版本 UE4SS + Lua 本地桥接 | 主要处理受支持的 UMG 文本；其他版本尚未开放同等适配 |
| Galgame / Windows x86/x64 文本 Hook | LunaHook 取词、翻译浮窗及可回填通道的内嵌 | 通道、编码、绘字和内嵌能力以具体游戏为准 |

引擎识别、取得文本、回传译文和最终画面是不同阶段。适配路线不保证所有游戏和文字控件可用。
不提供 OCR，图片或视频中无法直接提取的文字暂不覆盖。
公开分发目录不包含开发用截图和游戏验证记录，游戏详情不会提供这批内部记录。

## Flower Knight Girl Viewer

关闭 Viewer，在 Rika 游戏库添加实际运行的 EXE，重新检测后确认识别为 NW.js，再安装适配并重开 Viewer。
保持 Rika 运行，按正常方式逐句播放；译文异步显示在原对白位置，无需开启 Copy Text。
重复句使用缓存，快进或切场景时过期响应不会覆盖当前对白。服务不可用时继续显示原文并重试。

目标语言为中文且全局、游戏翻译开关均启用时，常用菜单、按钮、搜索标签、设置、提示和操作说明显示中文。
固定 UI 词条在本机转换，不调用翻译 API；暂停翻译后恢复原界面文字。
搜索输入、数值设置、快捷键和控件原有行为保留。角色名、自动补全结果、剧情选项、编辑框和图片文字暂未接入；未收录的 UI 文字保留原文。

安装会备份入口 HTML，并添加一个本机桥接脚本；剧情脚本、资源和存档保持原样。卸载按安装清单恢复，外部修改会保留并提示冲突。
游戏中仅保存本机桥接凭据，不保存上游 API Key。
修改服务、语言、词表或人工译文后，请重启 Viewer 清除进程内缓存。
已经安装 0.7.5 适配的用户，先关闭 Viewer 并在 Rika 卸载旧适配，升级工具后重新检测、安装，再启动 Viewer。

## Galgame 浮窗与内嵌

启动游戏后，在游戏详情连接对应进程，选择实际对白通道。角色名、逐字输出和系统消息可能是不同通道。
先检查浮窗译文；通道标为“可内嵌”时，可开启内嵌并设置等待时间。
译文未及时返回时，游戏继续显示原文，迟到的译文仍可进入浮窗和缓存。

浮窗支持透明背景、移动、缩放、滚动、原文显示、字体颜色和鼠标穿透。
鼠标穿透恢复快捷键优先使用 `Ctrl+Alt+T`，被占用时尝试 `Ctrl+Alt+F8`；两者均不可用时禁用穿透。
浮窗字号与内嵌比例独立。内嵌比例为 50–200%，100% 以游戏原字体为基准。
字体颜色设置作用于浮窗，游戏内嵌文字不提供同等颜色设置。

修改字体或内嵌字号后，BGI 等会缓存字形的游戏需要保存进度、完全退出并重新启动。
升级后已经注入旧版 LunaHook 的游戏也需要完全退出一次，以加载新 DLL。

## 字体

Unity 普通 UI 可选择系统字体；TMP 需要匹配版本的字体 AssetBundle，系统字体名不能代替 TMP 资产。
Ren’Py 和 RPG Maker 可导入 TTF/OTF。Unreal 使用游戏已加载的 Font 资源，不把普通字体文件直接当作 Unreal 资源。
“沿用已有 XUnity 字体”和“恢复游戏原字体”是不同选项。安装、替换或卸载前请查看备份及冲突提示。

## 用户数据与更新

API Key 和额外鉴权头通过 Windows DPAPI 保护，保存在自己的 `data/settings.json` 中。
本机服务默认监听 `127.0.0.1:17865`。上游 API Key 不传入游戏插件或 Hook 工作程序。
不要把自己运行后的 `data`、日志、备份、译文或服务配置放进公开仓库。

### 在线更新

从 0.7.7 开始，在 **设置 → 程序更新 → 检查更新** 获取本仓库的正式 Release。
查看版本和更新说明后点击“下载更新”；下载过程中显示进度，也可以取消。
工具核对完整包的大小、SHA-256 和程序文件，准备完成后才提供“安装并重启”。
点击“查看发布页”会通过系统默认浏览器打开 GitHub。
启动时不自动联网检查，不会自动强制安装。检查与下载不需要 GitHub 登录，也不会发送翻译服务的 API Key。

安装前保存设置、关闭正在翻译的游戏并断开 Hook。确认后工具安装新版并重新打开，
保留完整 `data`，包括设置、密钥、游戏库、译文、字体及适配器原始备份。
新更新默认不备份旧程序；若安装中断或启动检查失败，请关闭工具，用完整程序包修复原工具目录并保留 `data`。
成功重启后会清理本次更新的临时文件。历史更新任务原有的备份恢复仍可使用。

0.7.6 或更早版本需要先手动安装一次含在线更新功能的完整新版程序。
关闭工具与游戏，把完整 ZIP 解压后的程序文件更新到原工具目录，保留原 `data`。
不要只迁移 `settings.json`，也不要覆盖或删除原 `data`。

高级选项仍支持专用本地更新 ZIP；完整 Release ZIP 由在线更新功能处理，不能直接作为专用 ZIP 导入本地更新。

## 排查问题

- 没有译文：检查翻译开关、当前服务、模型、游戏适配状态及对白通道。
- API 请求失败：检查接口地址、模型、限流和可选参数。
- 中文缺字：检查字体字形覆盖、TMP 资产版本及具体游戏的绘字方式。
- 安装或恢复出现冲突：保留现有文件，查看安装清单和日志，不覆盖未知修改。

## 清理残留（0.8.1）

在游戏详情的“引擎适配”区域点击“清理残留”，先查看扫描出的移除、恢复和保留项目，关闭游戏后再确认清理。
正常安装的适配应先使用“卸载与恢复”；残留清理会按本工具的安装记录校验组件并恢复原文件，不会按文件夹名称删除其他工具的组件。
发现外部修改、原始备份损坏、游戏路径变化或同目录另一个条目仍有安装时，会暂停清理并保留文件。
原始文件备份默认保留；恢复完成后，可勾选同时删除旧备份，删除前再次确认。删除备份无法撤销。
未归属的组件、存档、工具译文与词表、导入字体、游戏运行期缓存和归档保留。清理后的游戏记录仍在库中，可自行重新安装或移出游戏库。

清理会先将 Unity 运行期翻译配置和 Ren’Py 对应编译缓存完整归档，再处理残留；归档保存在本工具数据目录的 `installations/<游戏标识>/generated`。这些归档不随旧备份删除。
