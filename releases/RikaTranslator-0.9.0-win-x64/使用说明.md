# Rika Translator（梨花翻译工具）0.9.0

Windows 10/11 x64 桌面工具。界面参考 XUnity Toolkit 的游戏库、侧边导航和分组卡片，支持用户自己的 OpenAI 兼容 API。当前是第一版试用构建，具体游戏兼容性需逐项验证。

0.9.0 新增“剧本翻译”：对受支持的 32 位 KiriKiri / Hxv4 游戏建立不含存档的临时副本，提取 PSB 场景对白；默认不选中、不调用 AI。可以勾选少量对白，也可以预览并确认后翻译当前剧本或全部待译。复用游戏已有服务与词表，支持暂停、保留进度、失败重试，以及导出已译 JSON / TXT、生成独立汉化补丁。临时副本需要额外磁盘空间，完成或取消后清理。当前已验证 DC5t4LM 的剧本读取，其他游戏逐项验证。

剧本翻译另支持已适配的 WillPlus / AdvHD 2.x UTF-16 消息记录（Scn.arc）、YU-RIS 494 的 YPF / YSTB（pac/Scripts.ypf）、ExHIBIT RLD 3（rld 目录）、Escu:de ESC-ARC2 / @mess 消息表（script.bin）、SiglusEngine Scene.pck。新增引擎离线读取，不启动游戏、不改游戏文件，复用相同的范围选择、多 API、MCP、术语表和进度保存功能。仅提取可识别的对白与受支持选项，不承诺覆盖所有菜单、图片文字或同引擎的其他版本。游戏库也可识别 ExHIBIT、Escu:de 的资源特征。新增引擎可将当前任务已完成译文回填到资源副本，再生成独立汉化补丁。未翻译部分保持原文，原游戏资源不覆盖；通过 RikaPatchLauncher.exe 加载，运行时无需梨花或 API。具体资源版本须通过写回校验，中文排版与剧情跳转需在游戏中验证。JSON / TXT 仍可用于译文交换。读取组件、源码和第三方许可见 `licenses/ScriptExtraction/`。

BGI / Ethornell 另支持 `Archive/data01*.arc` 原始剧本组的 ARC20 / DSC 压缩资源和 `BurikoCompiledScriptVer1.00` 字节码。已用《放課後シンデレラ２》验证，可选择 `Archive · 全部受支持剧本` 一次读取受支持章节，也可选择一份资源包；按对白、角色和选项记录提取，不把文件名或游戏指令作为对白。保留现有汉化包、存档与原始游戏文件。与其他新增引擎一样，支持 AI / MCP 翻译、导出及资源汉化补丁生成。

剧本页可选“多 API 分担”：勾选参与的服务并分别设置并发（每个 1–8，总计最多 16），没有手动限速设置。默认关闭，启用后仅向选定服务分配本次范围；遇到超时、限流或服务暂不可用会尝试其他可用服务，每批对同一服务最多尝试一次。各服务共用游戏语言、上下文、术语表及 AI 翻译页提示词，同一请求不混合不同场景，长对白保持整段。分句、变量和换行校验通过后保存进度及缓存；暂停或重启后可预览并“继续上次范围”，跳过已完成项。超时、断网或尚未保存结果时原服务仍可能计费，切换重试不能保证免除该费用。

剧本页也可选择“MCP 外部助手”：先勾选对白或选择当前剧本 / 全部待译，查看范围并确认准备，再由助手分批领取、翻译和回传。梨花验证编号、变量、标签和换行后原子保存；完全相同的重复回传不重复计入进度。此模式不调用梨花配置的 AI API，也无需配置翻译服务 Key。外部工具只可访问明确准备过的任务，不能自行创建提取任务、扩大范围、读取服务凭据或操作游戏文件。

外部助手模式下可保存“每批最多领取条数”，范围 1–50，默认 8 条。助手省略 `maxLines` 时使用此设置，也可用该参数进一步缩小条数；实际领取还受同场景、完整长段落和 8,192 字符原文总量限制。修改只影响新领取的批次，已经领取的批次仍可完整回传，批次设置与最多 50 条的未提交批次都会在重启后保留。更新程序后刷新助手中的 MCP 连接，以重新读取工具参数说明。

在“翻译方式”右侧复制 MCP 配置，按助手的配置方式添加并刷新连接；例如 Antigravity 可将其合并到 `mcpServers` 中。连接由 `RikaTranslator.exe --mcp --port 17865` 提供标准 MCP stdio，不需要另外安装 Python / Node；助手需要支持本地 stdio MCP，不同助手的配置格式可能不同。保持梨花主窗口打开，然后在助手里说：“用 rika_translator 领取梨花已准备的任务，按术语表翻译，逐批回传；完成或暂停后停止。”批次有效 15 分钟，助手可续期或归还；暂停会撤销未回传批次。主程序重启后已保存进度与未过期批次仍保留；外部连接更换后旧客户端尚未提交的批次可等到期归还，或在梨花暂停后重新准备。已保存的译文可用于预览、导出和生成汉化补丁。

在剧本任务中点击“生成汉化补丁”，预览后回填该任务所有已完成对白；不受当前筛选或勾选影响，也不再请求 AI。未译对白保留原文，角色名、图片和剧情指令不变。将生成的整个 `RikaPatch` 文件夹放到游戏 EXE 所在目录，运行其中的 `RikaPatchLauncher.exe`。从原 EXE 启动不加载补丁，移除时删除 `RikaPatch` 即可；原 EXE、XP3 和存档不覆盖。生成结果保存在本地任务目录 `data/script-translation/jobs/<任务编号>/patches/`，可从任务中的生成记录打开。当前适配校验有效的 PSB 3 和受支持的 32 位 KiriKiri / Hxv4 加载接口，游戏 EXE 与剧本内容均需匹配；其他版本会拒绝生成或保留原资源。更新译文后需重新生成。补丁不含翻译服务凭据，无需梨花或 AI 服务持续运行；加载器对应源码与许可随补丁提供，见 `licenses/ScriptPatch/`。实际排版需在游戏中检查，中文字体默认启用，可选择本机系统字体，也可点击“选择字体文件”从目录导入 TTF / OTF。文件会随补丁携带，以私有字体加载到游戏进程，退出游戏后释放，不安装到系统。选择的字体需包含中文；分享带字体的补丁前请确认字体允许再分发。

在线 / 本地更新会先关闭本程序目录的 MCP 连接，避免接口占用程序文件；更新后在助手中刷新 MCP。手动替换程序文件前，也可运行 `RikaTranslator.exe --stop-mcp` 关闭本目录的接口进程，随后正常退出主窗口再更新。

0.8.1 的游戏详情增加“清理残留”：先扫描并预览，确认后恢复原文件、移除可核验的本工具残留；正常适配先使用卸载与恢复。有外部修改或原始备份缺失时暂停清理，默认保留备份；恢复完成后可单独勾选删除旧备份。未归属的组件、存档、译文、导入字体及运行期归档保留。

0.8.1 修复 Unity 6（6000.x）版本识别，字体制作页可补查旧的空版本记录；游戏库卡片和列表新增移除按钮，搜索框去掉放大镜图标。移出游戏库不会删除游戏文件和存档，已安装本工具适配时需先卸载或恢复。

0.8.0 新增“字体制作”：本机 TTF/OTF → 静态 SDF TMP 字体包，无需 Unity 编辑器。提供 Unity 2018、2019、2020、2021、2022、6 的结构模板，并展示真实模板版本；具体游戏兼容性仍需验证。支持选择字符集、调整采样和图集、取消任务、导出成品，以及进入选中游戏的字体设置。

本版同时汇总 0.7.8 发布后的本机改进：预读句数可选 1–10、默认 3；AI 翻译页可断开所有 Hook 连接；已经校验的更新包会保留到下次打开并可直接安装或删除。自动预读目前支持已适配的 Flower Knight Girl Viewer 线性剧本及标准 RPG Maker MV/MZ 对话，其他游戏保持实时翻译。遇到选择、跳转、脚本、条件、变量修改或未知结构时停止预读，最多 8192 字符；较大句数可能增加未播放台词的 API 用量。

旧 Viewer/RPG Maker 适配需保存进度并关闭游戏后，在新版工具中卸载旧适配、重新安装，才能使用可调预读；后续修改句数通过本机心跳同步。程序更新不会自动改写游戏中的适配文件。

0.7.6 增加 Flower Knight Girl Viewer 的本地中文界面：菜单、按钮、搜索标签、设置和操作说明使用固定中文词条，界面显示不额外调用翻译 API。目标语言为中文且翻译已启用时生效，暂停翻译可恢复原界面文字。

0.7.5 新增 Flower Knight Girl Viewer 的逐句实时对白翻译：识别 NW.js Viewer，安装适配后按正常方式播放对白，译文异步显示在原对白位置。快进时丢弃过期显示结果，切换场景后自动重新绑定对白框。无需开启 Copy Text。

继续保留 0.7.4 的 Galgame 内嵌字号累计缩放修复：每次按游戏原字体计算比例，连续绘字和反复调整比例不会逐次缩小或放大；修复同名字体反复创建的问题。完整重编译并提供 32/64 位 LunaHook DLL。升级后，已经加载旧 DLL 的游戏需完全退出一次，再使用新工具连接。现有字体、字号和取词通道设置保留。完整程序目录、便携 ZIP 和对应源码按版本提供。

继续保留 0.7.3 的透明浮窗和字体颜色、0.7.2 的 Galgame 引擎识别、本机字体搜索和独立内嵌字号比例，以及 0.7.1 的界面缓存修复。《放課後シンデレラ２》识别为 BGI / Ethornell；引擎识别与游戏实际取词、内嵌能力分别验证。

## 在线更新（0.7.7）

在“设置 → 程序更新”点击“检查更新”，查看 GitHub 正式发布的版本和说明，再点击“下载更新”。
下载可取消；下载完成并通过 SHA-256 校验后，点击“安装并重启”。工具保留完整 data 中的游戏库、API Key、字体、词表、译文和适配器恢复资料，默认不备份旧程序。
0.8.0 会保留已经下载完成的更新包及待安装记录；关闭软件后重开会先离线校验，通过后可直接安装，不用重新下载。再次检查到同一程序包时复用；联网检查失败仍可安装已校验的缓存。设置页可“删除已下载更新”，损坏包或已被替代的缓存会清理，安装成功后自动清理大体积临时文件。旧版没有记录的孤立待安装包超过 7 天、不完整下载超过 1 天后清理，有恢复日志或备份的任务保留。
“AI 翻译”页的“断开所有 Hook 连接”会停止当前 Hook 会话及其未完成请求并隐藏浮窗，游戏继续运行；保存的字体、通道和连接偏好不变，未保存的翻译配置草稿也保留。
安装前保存设置并关闭正在翻译的游戏；没有旧程序备份时，安装中断或启动失败需要重新解压完整程序包到原目录，保留 data。
网络失败不会影响日常翻译。GitHub 匿名 API 限流时，会尝试通过公开发布页和校验文件检查更新，不要求 GitHub 登录或令牌。

发布者在 https://github.com/Furude-rika-mipa/RikaTranslator/releases 发布正式版本，标签用 v主版本.次版本.修订号；Assets 提供 RikaTranslator-同版本-win-x64.zip 和 SHA256SUMS.txt，沿用 0.7.6 的完整程序包格式。
ZIP 内最外层目录为 RikaTranslator-同版本-win-x64，保留 runtime、wwwroot、adapters 和 licenses，不包含个人 data。GitHub 自动生成的 Source code ZIP 不是在线安装包。
0.7.6 及更早版本没有在线检查入口，需要先安装一次带此功能的新版本，之后可在程序内下载更新。
本地专用更新 ZIP 的导入功能仍保留。新版构建不再附带内部验证截图和测试记录。

## 使用

1. 解压整个便携目录到可写位置，双击 `RikaTranslator.exe`。请整体保留 `runtime`、`wwwroot` 和 `adapters` 等目录；0.5.1 过渡版本的 DLL 仍在外层。旧的 ZIP 包仍是更名前版本。
2. 进入“AI 翻译”，添加服务，填写接口地址和 API Key，直接点击“获取模型”再选择模型 ID，无需先保存服务。模型 ID 是平台的接口模型名称，也可手动填写；本地无鉴权服务的 Key 可留空。获取模型不会保存草稿。
3. 保存后选择当前服务，主动点击测试连接。测试和模型列表获取会连接你填写的服务；测试连接会发生一次实际翻译请求。
4. 回到游戏库，添加游戏 EXE 或目录。查看引擎识别、当前适配能力和安装计划。
5. 对可适配的游戏，在关闭游戏后安装适配；查看备份与修改文件，再启动游戏。翻译时保持本工具运行。
6. 在游戏详情修改语言、当前服务或游戏背景。通过译文编辑器修改译文，通过词表统一角色、物品名称。
7. 查看游戏详情的“运行诊断”，分别确认组件部署、加载记录、收到游戏文字和回传译文，再检查游戏画面。诊断每 3 秒更新，不覆盖未保存的设置。
8. 若需恢复，在关闭游戏后卸载适配。工具只恢复自己修改的文件，遇到后续改动保留文件并报告冲突。Unity 自动扩展的翻译配置会先完整归档，生成的 interop、日志和译文缓存保留。
9. 游戏详情提供“替换字体”：可选择自动中文字体、保留游戏原字体或自定义字体。已安装适配时先关闭游戏，保存会直接更新受工具管理的配置，重新启动游戏生效；未安装时先保存，随适配安装应用。“恢复自动”回到工具默认字体，卸载适配恢复最初备份。

字体按引擎处理：Unity UGUI 选择本机系统字体，TMP 另选匹配游戏 Unity/TMP 版本的字体 AssetBundle，可选后备或统一替换；Ren’Py 和 RPG Maker MV/MZ 导入 TTF/OTF，字体复制到工具的 `data/fonts`，此后不依赖原文件位置。Unreal 选择游戏已加载的 Font 对象路径和字形（例如 `/Engine/EngineFonts/Roboto.Roboto`、`Regular`），这版不把普通 TTF/OTF 转成 Unreal 资源。找不到所选资源时保留原字体，并在运行诊断中提示。自定义控件和字符覆盖仍需具体游戏验证。

侧栏“字体制作”可将本机 TTF/OTF 制作为静态 SDF TMP 字体包，无需 Unity 编辑器或翻译 API。提供 Unity 2018、2019、2020、2021、2022、6 的结构模板，页面展示模板真实版本；兼容范围与具体游戏仍需验证，不能保证所有补丁版本通用。可选常用简中、基本汉字或自定义字符，并调整采样大小、图集与留白；最多自动生成 4 页图集，超出时明确提示，不静默丢字。制作在独立进程中执行，可取消；原 TTF/OTF 保留，成品和报告存入 `data/font-maker/generated`。可导出字体包，或点击“用于选中的游戏”进入现有字体设置，保存前不会改动游戏。建议先用 TMP 后备字体，补足原字体缺少的字符。

工具依赖 Microsoft Edge WebView2 Runtime。当前电脑已具备该运行时；其他电脑缺少时，请从[微软官方页面](https://developer.microsoft.com/microsoft-edge/webview2/)安装。便携包包含 .NET 运行时，无需另装 Python、Node.js 或 .NET SDK。

## Flower Knight Girl Viewer 实时翻译与中文界面（0.7.6）

1. 先关闭 Viewer，在 Rika 的游戏库打开或添加 `Flower knight girl Viewer.exe`，确认识别结果为 NW.js。 如果此前开启过此游戏的 Galgame Hook 自动连接，请关闭该开关；已保存的通道参数可以保留。
2. 选择翻译服务和语言，安装适配。工具会备份入口 HTML，并新增一个本机连接脚本；不改写原始剧情文件。
3. 重新启动 Viewer，保持 Rika 运行。每次出现新的对白，先显示原文，再在同一位置显示译文；跳到下一句后，上一句迟到的结果不会覆盖当前对白。
4. 服务暂不可用时显示原文；重复对白使用缓存。暂停或恢复全局/游戏翻译开关会在数秒内同步，无需为暂停开关重启 Viewer。

## Galgame 实时翻译（0.7.0）

1. 在“AI 翻译”配置自己的 OpenAI 兼容服务，选择模型并测试连接。添加游戏实际使用的 EXE，在游戏详情设置原文语言、目标语言与服务。
2. 先启动游戏，在详情的“Galgame 文本 Hook”选择游戏进程并连接；也可启用 Hook 后从工具启动游戏。连接只在运行进程中加载组件，游戏目录不写入适配文件。首次连接默认关闭内嵌。
3. 在游戏中显示一段对白，查看取词通道的预览。选择确实包含对白的通道；角色名、逐字绘制和系统通道可能分别出现。只有选中的通道会进入翻译队列。工具保存通道的 Hook 代码与上下文，重新连接后遇到相同通道会恢复选择；无法匹配时重新选择。
4. 先查看浮窗的原文和译文。浮窗没有顶部栏，文字间的背景透明，可直接看到下方游戏画面；文字带黑色阴影。拖动文字移动位置，右下角调整大小，长段文字可用滚轮查看，右键菜单可复制整段原文/译文或隐藏浮窗。“字体与显示”可搜索本机字体的中英文名称、选择并预览，也可手动填写名称；可选择浮窗字体颜色或填写 #RRGGBB，浮窗字号与是否显示原文分别设置。浮窗保持置顶。勾选鼠标穿透后，用浮窗注明的快捷键恢复操作：优先 Ctrl+Alt+T，被占用时尝试 Ctrl+Alt+F8；两者不可用时禁用穿透，避免无法恢复。
5. 通道标为“可内嵌”时，可在“字体与显示”启用游戏内嵌，并设置等待上限（200–5000 毫秒）。译文需在期限内返回才能交给本句内嵌；超过期限，游戏继续显示原文，迟到的译文仍进入浮窗与缓存。首个未缓存句子常会超过期限，适合先用浮窗，或先看过一遍再用缓存。游戏字形和布局仍需目视检查。
6. 没有有效通道时，可切换编码（Shift-JIS、GBK、Big5、UTF-8、UTF-16）、启用通用系统 Hook 后重新连接，或输入适用于该游戏版本的手动 Hook 代码。删除已保存代码后重启游戏才能完全移除其运行状态。没有取词、通道消失、API 失败、内嵌超时均可在游戏日志中查看。

“整句重复去重”只合并整段完全相同的重复副本，最多 8 份，单份至少 4 个字符；真实对白有重复时可关闭。已有汉化补丁可能同时输出原文与译文，逐字通道也可能产生重复，应选正确通道。多次停止和重新连接后若出现异常重复，请重启游戏再连接。

浮窗字体用于浮窗；可内嵌通道同时把字体名称交给 LunaHook，是否改变游戏字体取决于其内嵌方式。字体颜色仅改变浮窗原文和译文，不改变游戏内嵌文字颜色。它不会修改原有 XUnity 的字体配置。Hook 编码和等待时间也按游戏保存。同一时刻只连接一个 Hook 游戏；“停止连接”后游戏继续运行，重启游戏可完全清除本次注入状态。全局或游戏翻译暂停时不调用服务；恢复后会重新处理当前原文。

“内嵌字号（%）”与浮窗字号分开保存，范围 50–200%。100% 保持游戏原字号，80% 缩小、120% 放大。它将比例交给 LunaHook 的游戏字体拦截；在可内嵌通道启用内嵌后，重新显示文字检查，个别游戏需重启，自定义绘字可能不受影响。本机字体列表不保证每个字体都包含所需汉字，请先查看预览。

0.7.4 已将字体基准与缓存修复编译进完整 LunaHook DLL，并同步组件 SHA-256 校验清单。0.7.3 旧进程中已经累积缩放的字体状态需要通过完全退出游戏清除；只停止 Hook 或保存 100% 不能可靠恢复。测试、对应源码和构建方法见 [内嵌字号修复记录](licenses/galgame/RikaLunaHook-fontfix/README.md)。

《放課後シンデレラ２》游戏副本已用本机模拟服务验证开场对白：重启后 70%、100%、120% 的中文均正常显示，继续切换对白后 70% 字形保持稳定。这个游戏缓存已绘制字形，实时修改比例可能混用新旧大小；修改字体或内嵌字号后，请保存进度并完全重启游戏。实测记录与原始截图在 `validation/BGI-font-0.7.4-验证结果.json` 和相邻 PNG，尚未验证完整剧情及其他 BGI 游戏。

验证用的是 9-nine- 新章的 **nine_new_chs.exe 汉化版副本**，目标语言为英语、本机模拟服务。画面已显示“English translation test”，并验证慢请求保留原文。原始 nine_newEP.exe 在测试副本提示缺少“软件电池运行库”，没有进入剧情；不能把汉化版结果作为原始 EXE 已通过的证据。完整剧情、菜单、选项、存档、其他 Galgame 及真实模型质量仍待验证。具体记录与截图在 `validation` 和 `测试记录.md`。

## API 与数据

- 支持基础地址、带自定义前缀的地址和完整 `/chat/completions` 地址，支持普通 JSON 返回与 SSE 流式返回。
- 提供可选 temperature、输出长度、额外请求头和额外 JSON 参数；不自动改用其他提供商。
- 使用同一个原文、服务、模型和相关设置的有效缓存，人工修订优先。切换服务、凭据或影响译文的设置会区分缓存。
- 上述规则适用于本工具服务端缓存。RPG Maker、Ren’Py、NW.js 和 Unreal 还有游戏进程内缓存：修改服务、语言、提示词、词表或人工译文后，重启游戏才会重新读取。Unity 使用 XUnity 自身缓存；修改目标语言请关闭游戏、卸载适配，再按新语言重新安装，旧译文缓存仍可能需要备份后移开。Unreal 修改语言后也需卸载再安装，以刷新语言过滤和字体设置。第一版尚未同步刷新这些游戏端缓存。
- Galgame Hook 复用服务端缓存、词表、上下文及人工译文。更改服务、语言或翻译设置会取消旧队列，重新处理当前原文供浮窗查看；内嵌按后续游戏取词事件处理，旧响应不会覆盖新语言或新通道。
- API Key 和额外请求头值通过 Windows DPAPI 保护，位于 EXE 旁的 `data/settings.json`。只有当前 Windows 用户可解密，不把上游 Key 写入游戏插件。
- 游戏插件使用本机连接凭据，服务仅监听 `127.0.0.1:17865`。其他软件占用端口时工具会报告启动失败。
- Unreal 使用游戏 Shipping 程序旁的 `ue4ss/Mods/GameTranslateToolkit/ipc` 交换临时原文和译文；游戏线程不等待网络，API Key 不进入游戏。临时文件仅保存在本机，收到后移除；卸载时先归档已知残留和加载日志，不触碰未知模组或存档。
- 默认日志记录状态和错误，完整原文和译文保存在译文数据中，日志不记录完整请求或响应正文。日志可按游戏、级别和模块筛选、复制或导出。
- 日志文件按日期和大小轮转，保留最多 14 个文件。翻译数据导出不包含 API Key、额外鉴权头值和游戏连接凭据。
- `data/installations` 保存安装清单和恢复备份。更换工具目录时请连同 `data` 一起移动；清理前先卸载已安装适配。

## 故障排查

- 没有译文：确认工具处于启用状态，已选择有效服务和模型；查看游戏适配状态与运行日志。
- IL2CPP 首启较慢：运行诊断和 `BepInEx/LogOutput.log` 会显示基础库下载与 interop 生成。等待准备完成；若下载或生成失败，查看错误记录。下载基础库不调用翻译 API。
- API 失败：检查地址、模型、余额或限流，先主动测试连接。接口不支持某个可选参数时关闭该参数；不要把无效响应当作译文。
- 出现缺字：检查引擎字体和自定义文本组件。适配使用的字体不代表所有文字控件都已兼容。
- Unity 2022 的中文目标自动配置随包 TMP 中文后备字体；其他 Unity/TMP 版本仍需匹配对应字体资产。后备字体保留原控件字体已有字符，具体布局需在游戏中检查。
- Unreal 中文回填尝试使用游戏自带 Roboto 和引擎回退字库，保留字号、材质和描边，会改变字形。若游戏缺少此字库或自定义绘制，需要另做字体适配。布局较小的按钮可能需要缩短译文，可在译文编辑器修订后重启游戏。
- 无法安装：先关闭游戏，检查写入权限和已有插件冲突；不要覆盖工具报告存在冲突的文件。
- 卸载报告冲突：文件可能被游戏更新、其他插件或用户修改。原文件与备份保留，按日志和安装清单处理。

- 游戏详情按具体游戏文件匹配验证记录。MZ 1.5.0 副本在 0.5.0 验证设置页、开场文字、选项、中文字体、重启缓存及卸载恢复；Lunar 与 YandereKamikakushi 保留旧版本历史结果。其他游戏、不同文件版本和未覆盖控件显示未验证。完整范围及截图位于程序旁的 `validation`。

从 0.4.0 更新到本版：设置 → 本地更新 → 选择 `RikaTranslator-0.5.0-本地更新.zip` → 校验更新包 → 确认更新并重启。ZIP 是专用更新包，不需要手动解压到游戏目录。当前用户程序保持 0.4.0，供用户亲自安装验证。

更新程序不会自动更改已安装到游戏的适配器。RPG Maker MV/MZ 要使用本版新增的状态报告，退出游戏后在详情页卸载与恢复，再安装适配。原有译文仍保留；图片文字继续不覆盖，本版不提供 OCR。

## 0.6.0 运行目录

DLL、原生运行库、依赖 JSON 和语言资源集中到 `runtime`，启动 EXE 保留在外层。`.NET` 启动器直接加载 `runtime/RikaTranslator.dll`，网页、适配器、验证记录和 `data` 仍从外层读取。字体检查子进程、独立更新器及后续更新均支持这种结构。不要手动拖动旧版 DLL 或只复制 EXE。

0.4.0 / 0.5.0 用户从“设置 → 本地更新”按顺序安装 `01-RikaTranslator-0.5.1-过渡更新.zip`，重启后再安装 `02-RikaTranslator-0.6.0-目录整理更新.zip`。旧更新器要求运行 DLL 位于外层，所以必须先经过 0.5.1；这是包格式兼容所需步骤。更新会校验并备份旧运行文件，仅移除匹配清单的文件，未知或被修改的文件保留。失败回滚恢复平铺结构及原程序，用户数据保持原位置。两轮更新需为暂存与备份预留足够空间，建议至少 3 GB。

后续 0.6.x 可以直接使用新布局的本地更新包。制作运行目录更新包时，最低版本设为 0.5.1 或更高；首次目录迁移通过 `-LegacyDirectory <0.5.1 发布目录>` 写入旧文件校验清单。

## 0.7.1 本地更新与分发

0.6.0 / 0.7.0 用户在“设置 → 本地更新”选择 `RikaTranslator-0.7.1-本地更新.zip`，校验后确认更新并重启。先关闭正在翻译的游戏。现有游戏库、服务与加密 Key、字体、人工译文、词表、缓存和恢复备份保留；游戏中的既有 Unity / Ren’Py / RPG / Unreal 适配不会自动重装。旧于 0.6.0 的版本先按原步骤过渡到 0.6.0，再安装本包。

0.7.4 本次只输出干净的 `RikaTranslator-0.7.4-win-x64` 程序目录，不生成便携或本地更新 ZIP。给其他人使用可以自行压缩完整的干净目录，保留所有子目录及许可证/源码目录，运行 `RikaTranslator.exe`。首次运行生成自己的 `data`。分享已经使用过的目录前，移开个人 `data`，不要把服务配置和游戏数据一起分发。不要只复制 EXE。
